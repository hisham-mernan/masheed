# مَشيد — المخطط الشامل للمنظومة (System Blueprint)

> **التاريخ:** 2026-09-12
> **الغرض:** تصور كامل لمنظومة إدارة وبيع الأوقاف في المملكة العربية السعودية، مكوّنة من نظامين مترابطين:
>
> 1. **مَشيد ERP** — نظام إدارة الأوقاف (أوقافنا + أوقاف العملاء).
> 2. **وقف باي مَشيد (WaqfBuy)** — منصة بيع حصص الأوقاف (عادية أو مُرمّزة Tokenized) للمواطنين والمقيمين.
>
> الوضع الحالي للكود يمثل تقريباً **1/20** من هذه الرؤية. هذا المستند يعرّف الـ 20/20.

---

## 1. الرؤية والمبادئ

- **رقمنة كاملة لدورة حياة الوقف**: من التأسيس والتسجيل، إلى إدارة الأصول والريع والتوزيع، إلى بيع الحصص والترميز، إلى التقارير والحوكمة.
- **لا أتمتة عمياء**: كل قرار مالي أو شرعي يمر بـ **موافقة بشرية** موثّقة (Maker–Checker). النظام يقترح ويحسب، والبشر يعتمدون.
- **كل حركة لها أثر**: Audit log إلزامي على كل جدول مالي/قانوني.
- **الفصل بين النظامين مع تكاملهما**: ERP للإدارة الداخلية، WaqfBuy للجمهور؛ يرتبطان بطبقة تكامل (API + أحداث) وليس بقاعدة واحدة مكشوفة.
- **الامتثال السعودي أولاً**: الهيئة العامة للأوقاف، نفاذ/التحقق الوطني، ضوابط هيئة السوق المالية (CMA) لطرح الأدوات المُرمّزة، ومكافحة غسل الأموال (AML/KYC).

## 3. المستخدمون والأدوار (Personas & Roles)

### 3.1 منصة الإدارة — مَشيد ERP

| الدور | الوصف | صلاحيات أساسية |
|---|---|---|
| **مدير المنصة (Platform Admin)** | موظفو مَشيد | كل شيء على كل الأوقاف، إدارة العملاء والاشتراكات، التسويات |
| **مدير وقف (Waqf Admin)** | مسؤول العميل عن وقف/أوقافه | إدارة كاملة داخل وقفه: أصول، مستفيدون، مالية، مستخدمون |
| **ناظر وقف (Trustee)** | الناظر الشرعي للوقف | اعتماد القرارات الكبرى (توزيع، بيع أصل، طرح حصص) — توقيع إلكتروني |
| **مشرف عمليات (Supervisor)** | موظف تشغيل | إدخال وتعديل تشغيلي، لا يعتمد ولا يحذف |
| **محاسب (Accountant)** | مالية | قيود، فواتير، تسويات، تقارير مالية؛ لا يصرف بدون اعتماد |
| **مدقق (Auditor)** | داخلي/خارجي | قراءة كل شيء + سجل التدقيق، لا كتابة |
| **مشاهد (Viewer)** | متابعة فقط | قراءة محدودة |
| **مسؤول شرعي (Sharia Officer)** | رقابة شرعية | اعتماد شرعي على التوزيعات والمنتجات المُرمّزة، فتوى موثقة |

### 3.2 منصة البيع — WaqfBuy

| الدور | الوصف |
|---|---|
| **مستثمر مواطن/مقيم (Investor)** | يشتري حصصاً وقفية، يستلم توزيعات، يتابع محفظته |
| **مالك/ناظر طارح (Issuer)** | يطرح وقفه للبيع عبر المنصة (يمر بدورة اعتماد) |
| **مسؤول امتثال (Compliance Officer)** | مراجعة KYC/AML، تجميد حسابات، بلاغات |
| **دعم عملاء (Support)** | تذاكر ومساعدة، صلاحيات محدودة جداً على الحسابات |

> قاعدة عامة: **Maker–Checker** على كل عملية مالية — من ينشئ لا يعتمد، ومن يعتمد لا ينشئ.

## 4. النظام الأول: مَشيد ERP — الوحدات الكاملة

### 4.1 إدارة الأوقاف (Waqf Registry) — *موجود جزئياً ✅*
- ملف وقف كامل: صك الوقفية، رقم التسجيل لدى الهيئة العامة للأوقاف، الناظر، الشروط الشرعية (شرط الواقف)، الحالة (نشط/قيد التأسيس/منتهٍ).
- تعدد الأوقاف مع مبدّل نطاق — *مبني ✅*.
- دورة حياة الوقف: تأسيس → توثيق → تشغيل → تقييم سنوي → (تحويل/انتهاء).
- أرشفة مستندية لكل وقف.

### 4.2 إدارة الأصول (Assets) — *موجود جزئياً ✅*
- أنواع: عقاري، زراعي، استثماري، نقدي، أسهم/صناديق، **حصص مُرمّزة**.
- لكل أصل: تقييمات دورية، عقود إيجار، صور ومستندات، إحداثيات، حالة (نشط/صيانة/معروض للبيع/مباع).
- ربط الصيانة بحالة الأصل — *مبني ✅*.
- تقرير قيمة سوقية vs دفترية.

### 4.3 المستفيدون والتوزيعات — *موجود جزئياً ✅*
- فئات مستفيدين، أسهم، أهلية دورية (مستندات إثبات، مراجعة سنوية).
- **دورة توزيع كاملة بشرية**: حساب مقترح → مراجعة محاسب → اعتماد ناظر + مسؤول شرعي → صرف → إثبات صرف لكل مستفيد (تحويل/شيك/نقد) — حالياً الصرف آلي بزر واحد ❌ يجب تفكيكه لدورة اعتماد.
- إشعارات للمستفيدين + كشف استلام.

### 4.4 المالية والمحاسبة (Finance & GL) — *جزئي ❌*
- دليل حسابات (Chart of Accounts) لكل وقف، قيود يومية مزدوجة، فوترة إيجارات، تحصيلات، مصروفات.
- موازنات سنوية واعتمادها.
- تسوية المحافظ — *RPC مبني ✅* لكن بلا دورة اعتماد.
- تقارير: قائمة دخل، مركز مالي، تدفقات نقدية، تقرير الهيئة.

### 4.5 الصيانة والعمليات — *موجود ✅ أساسي*
- مهام، طلبات صيانة من مستأجرين، عقود مقاولين، تكاليف مربوطة بالأصول، SLA وتصعيد.

### 4.6 المستندات والعقود — *موجود جزئياً ✅*
- مكتبة مستندات مع تصنيف وانتهاء صلاحية وتنبيهات (صك، عقد إيجار، رخصة).
- توقيع إلكتروني (تكامل مع موثق/منصات التوقيع السعودية).
- قوالب عقود جاهزة.

### 4.7 الاستثمار (Investment)
- محافظ استثمارية للأوقاف، أدوات (صكوك، صناديق، ودائع)، سياسة استثمارية معتمدة شرعياً، قياس أداء مقابل مؤشر.

### 4.8 الحوكمة وسير العمل (Governance & Workflow) — *غائب ❌*
- **محرك طلبات واعتمادات موحّد**: كل قرار (توزيع، بيع أصل، تعيين مستفيد، طرح حصص، صرف مالي) = طلب له حالة: مسودة → مراجعة → اعتماد ناظر → اعتماد شرعي → تنفيذ → أرشفة.
- مصفوفة صلاحيات لكل وقف (من يعتمد ماذا وحدود المبالغ).
- اجتماعات مجلس النظار ومحاضرها وقراراتها مربوطة بالطلبات.

### 4.9 التقارير والتحليلات — *جزئي*
- لوحات: أداء الريع، إشغال الأصول، التوزيعات، التزام شرعي، مؤشرات الهيئة.
- **تقرير شهري PDF لكل وقف** (إيرادات/مصروفات/توزيعات) — *الخطوة التالية المقترحة*.
- تقارير امتثال دورية للهيئة العامة للأوقاف.

### 4.10 إدارة العملاء (لأوقاف الغير) — *غائب ❌*
- حسابات عملاء (جهات مالكة لأوقاف تديرها مَشيد)، اشتراكات SaaS، فوترة، SLA، نسبة إدارة.
- عزل كامل بين بيانات العملاء (Multi-tenancy — موجود مبدئياً عبر waqf_id + RLS ✅).

## 5. النظام الثاني: وقف باي مَشيد (WaqfBuy) — منصة البيع

### 5.1 الفكرة
منصة تتيح للمواطنين والمقيمين شراء **حصص في أوقاف منتِجة** — إما:
- **حصص تقليدية**: وحدات ملكية منفعية مسجلة دفترياً داخل المنصة، عوائدها توزع دورياً.
- **حصص مُرمّزة (Tokenized)**: توكنز رقمية تمثل الحصة على شبكة مرخّصة، قابلة للتداول في سوق ثانوي (وفق ضوابط CMA).

### 5.2 الرحلات الأساسية

**رحلة المستثمر:**
1. تسجيل → تحقق هوية عبر **نفاذ (Nafath)** → KYC/AML.
2. تصفح الفرص: صفحة لكل طرح (الأصل، التقييم، العائد المتوقع، الشروط الشرعية، درجة المخاطرة، المستندات).
3. شراء: محفظة نقدية (شحن عبر مدى/Apple Pay/تحويل) → تأكيد → إصدار حصة/توكن.
4. محفظة المستثمر: حصصي، توزيعاتي المستلمة، كشوفات، شهادات ملكية PDF.
5. سوق ثانوي (مرحلة لاحقة): عرض/طلب بين المستثمرين بضوابط.

**رحلة الطارح (مالك الوقف):**
1. طلب طرح من داخل ERP → تقييم مستقل → اعتماد ناظر + شرعي + امتثال المنصة.
2. نشرة طرح (مستند موحّد) → فتح نافذة اكتتاب → تخصيص → تحصيل → إصدار.

### 5.3 الترميز (Tokenization) — بنية محافظة
- **سجل التوكنز (Token Registry)** داخل قاعدة المنصة هو المصدر القانوني؛ أي تمثيل على بلوكتشين مرآة له.
- معيار التوكن: ERC-3643 (أو ما يعادله — هوية مُلزمة، قيود تحويل، تجميد) على شبكة مرخّصة/مغلقة.
- حارس مفاتيح (Custody): محافظ مُدارة للمستثمرين غير التقنيين، خيار self-custody للمتقدمين.
- قيود: حد أقصى للملكية الفردية، فترة حظر (Lock-up)، منع التحويل خارج هويات موثقة.

### 5.4 الامتثال
- KYC/AML: تحقق نفاذ + فحص قوائم عقوبات + مراقبة معاملات وحدود.
- ضوابط CMA للطروحات الرقمية (حالة بكل طرح: مسودة/قيد المراجعة/معتمد/مطروح/مغلق).
- تقارير للجهات + سجل غير قابل للتعديل.

- `accounts` (دليل حسابات) · `journal_entries` + `journal_lines` (قيود مزدوجة)
- `budgets` · `invoices` · `payments`

**العملاء والاشتراكات:**
- `organizations` (الجهات المالكة) · ربط `waqfs.organization_id`
- `subscriptions` · `invoices_billing`

**WaqfBuy:**
- `offerings` (طرح: وقف/أصل، عدد وحدات، سعر، حالة، نشرة)
- `investor_profiles` (KYC، حالة تحقق، تصنيف مخاطر)
- `wallets` + `wallet_ledger` (محافظ نقدية)
- `orders` (شراء/اكتتاب) · `holdings` (ملكيات)
- `token_registry` (توكن: معيار، عنوان، حالة) · `payouts` (توزيعات للمستثمرين)
- `secondary_listings` (لاحقاً)

**مشترك:**
- `notifications` · `tickets` · `workflow_definitions` · `e_signatures`

## 9. فجوات الوضع الحالي (Gap List) — للتنفيذ الفوري

1. **دورة اعتماد للتوزيع والتسوية** بدل الصرف الآلي — `approval_requests` + حالات.
2. **قيود محاسبية حقيقية** خلف كل transaction.
3. **صفحة تقارير شهرية PDF** لكل وقف.
4. **إشعارات داخلية** للأحداث (مهمة متأخرة، عقد ينتهي، طلب بانتظارك).
5. **دورة أهلية المستفيدين** (مراجعة سنوية + مستندات).
6. **إدارة مستخدمي الوقف** من واجهة الإدارة (دعوة/تغيير دور/تعطيل) — *جزئياً موجود (addUserProfile)*.
7. **سجل بحث وتدقيق قابل للتصفية والتصدير**.

> كل بند أعلاه يُنفَّذ مع اختبار e2e حقيقي (مستخدم بشري يمر بالفلو كاملاً)، وليس مجرد صفحات تنقّل.
